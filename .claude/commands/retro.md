완료된 계획(또는 최근 작업 구간)에 대한 회고 데이터를 수집·분석해줘.
이 시스템(plan/team-run)이 실제로 작동하는지 측정하는 도구다. 감이 아니라 데이터로 튜닝한다.

## 데이터 수집

1. `.claude/docs/kanban.md`에서 팀 ID 확인
2. 대상 선정: $ARGUMENTS로 계획 문서가 지정되면 그 계획의 태스크들,
   없으면 최근 아카이브된 계획(`.claude/docs/plans/archive/` 최신) 또는 최근 Done 태스크 전체.
   **생존 편향 방지**: 기간 내 Rejected·블로커 이력이 있는 태스크는 현재 상태와 무관하게
   반드시 포함한다 — 시스템의 문제는 성공한 태스크보다 죽은 태스크에 더 많이 담겨 있다
3. `get_board` + 각 태스크의 `get_task_detail`로 노트 이력 수집
4. `git log`로 같은 기간의 커밋 이력 수집

## 분석 항목

### 리뷰 실효성
- 태스크별 Reviewer FAIL 횟수와 사유
- **러버스탬프 비율**: 전체 리뷰 중 1차 PASS 비율. 100%에 가까우면 리뷰어가 결함을
  못 잡는 것인지, 구현 품질이 좋은 것인지 FAIL 사유의 질로 판별
- FAIL 사유 중 "완료조건 미충족" vs "스코프 밖 변경" 분포

### 프로세스 마찰
- 태스크별 자체 QA 루프 횟수: `QA-FAIL n회차` 노트를 센다 (MAX_QA_LOOP 근접 빈도).
  QA-FAIL 노트 없이 실패가 의심되는 정황(반복 수정 커밋 등)이 보이면 "계측 누락"으로 별도 보고
- 블로커 발생 횟수와 사유 분포 (전제 충돌 / 외부 의존 / 기타)
- [human] 확인 대기가 흐름을 막은 횟수: `flow-blocked` 노트를 센다
- handoff 노트 스키마 준수율 (필수 항목 누락 빈도) — 어떤 규칙이 안 지켜지는지의 신호

### 우회 측정
- **보드 밖 커밋**: 기간 내 커밋 중 태스크 ID가 없는 커밋 목록.
  이 비율이 높으면 프로세스가 우회되고 있다는 신호 (경량 경로 /quick 필요성의 근거)
- **기준선**: 커밋 컨벤션(태스크 ID) 도입 시점 이후의 커밋만 센다.
  도입 이전 이력이 섞이면 전부 오탐이다. 첫 회고에서는 이 한계를 보고서에 부기하라
- **분류 표기**: merge 커밋, 의존성 업데이트 같은 정당한 무태스크 커밋은
  "정당한 예외"로, 나머지는 "우회 의심"으로 구분해 표기한다

## 보고 형식

```
## 회고: <계획명 / 기간>
### 요약: 태스크 N개 / 1차 PASS율 n% / 블로커 n건 / 보드 밖 커밋 n건
### 리뷰가 실제로 잡은 결함: (FAIL 사유 목록, 없으면 "없음 — 러버스탬프 의심 여부 평가")
### 가장 자주 깨진 규칙: (노트 스키마 누락, 상태 전이 누락 등)
### 튜닝 제안: N_DONE / MAX_QA_LOOP / MAX_REVIEW_FAIL 조정 근거, /quick 필요 여부
```

수치가 부족하면 부족하다고 보고하라. 데이터 없이 "잘 되고 있다"고 결론내리지 마라.

## 결과 소비 (증발 방지)

1. 보고서를 `.claude/docs/retros/retro-YYYYMMDD.md`로 저장한다. 채팅 출력만으로 끝내지 마라
2. 튜닝 제안을 사용자가 승인하면: team-run.md의 튜닝 파라미터 값을 수정하고
   조정 이력에 한 줄 기록 — 예: `N_DONE 3→2 (retro-20260715 근거)`.
   이 이력이 있어야 다음 회고가 "지난 튜닝이 효과 있었나"까지 평가할 수 있다

## 교훈 승격 (반복 방지 — 기록을 지시로 증류)

handoff 노트의 서사 필드(문제와 해결/버린 접근)와 블로커·FAIL 사유에서
**재발 가능성이 있는 교훈**만 추려 사용자 승인 후 `.claude/docs/lessons.md`에 추가한다.
이 파일은 /plan과 /team-run이 시작 시 읽는다.

- **형식**: 한 줄 지시형 — "~하지 마라 / ~할 때는 ~하라" + 근거 회고 표기.
  예: `- SQLite WAL 모드에서 스키마 변경 시 -shm/-wal 파일 잠금 확인 (retro-20260710)`
- **승격 금지**: 일회성 사실, 이미 CLAUDE.md에 있는 규칙, 특정 태스크에만 유효한 내용
- **상한 20줄 (큐레이션 필수)**: 초과 시 오래된 것부터 통합·삭제를 제안하고 사용자 승인을 받는다.
  비대한 교훈 파일은 지시 무시를 유발한다 — 무한 축적이 아니라 증류가 목적이다.
  충분히 검증돼 영구 규칙이 된 교훈은 CLAUDE.md 승격을 제안하고 lessons에서 제거

## 보드 발행 (대시보드 소비용)

파일이 원본, 보드는 게시판이다. 대시보드(다기기 동기화)에서 회고·교훈을 보기 위한 발행 단계:

1. **회고 발행**: `create_task`로 `[retro] YYYYMMDD <계획명>` 태스크를 생성하고
   description에 보고서의 "요약 + 리뷰가 잡은 결함 + 가장 자주 깨진 규칙 + 튜닝 제안"을 다이제스트로 담는다
2. **교훈 발행**: lessons.md가 변경된 경우, `[lessons] 프로젝트 교훈` 태스크(없으면 생성)에
   `add_note`(progress)로 lessons.md 전문 스냅샷을 게시한다 — 최신 노트가 곧 현재 교훈
3. `[retro]`/`[lessons]` 태스크는 실행 대상이 아니다 (team-run이 후보에서 제외).
   상태 전이·할당 없이 Backlog에 그대로 둔다 — 대시보드가 타이틀 프리픽스로 전용 뷰에 렌더링한다
