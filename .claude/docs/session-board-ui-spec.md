# session_board 화면 설계 명세: 칸반 인사이트 뷰

agent-kanban 워크플로우(/plan → /plan-run → /retro)가 남기는 기록을 사람이 소비하는 화면 명세.
데이터 원천은 기존 tasks/notes 테이블 그대로 — **새 스키마 없이 렌더링 규칙만 추가**한다.

## 설계 원칙

- 기계가 남기는 노트는 고정 프리픽스 스키마를 따른다 → UI는 프리픽스를 파싱해 렌더링한다
- 유저의 질문 4계층에 뷰를 대응시킨다:
  1. "지금 뭐 하고 있어?" → 보드 카드 뱃지
  2. "이 태스크에서 무슨 일이 있었어?" → 태스크 상세 타임라인
  3. "이번 사이클이 어땠어?" → `[retro]` 뷰
  4. "그래서 뭘 배웠어?" → `[lessons]` 뷰

## 노트 파싱 규칙 (데이터 계약)

| 노트 패턴 | note_type | 의미 |
|---|---|---|
| `QA-FAIL n회차: <사유>` | progress | 자체 QA 실패 (n = 누적 횟수) |
| `flow-blocked: [human] 대기 — ...` | progress | 사람 확인 대기로 흐름 정지 |
| `human-verified: <항목> — 사용자 확인, <일시>` | review | 사람이 완료조건 확인함 |
| handoff 스키마 (아래 필드 구조) | handoff | 태스크 마무리 인계 노트 |
| PASS / FAIL(사유) | review | Reviewer 판정 (Reviewer 에이전트 ID로 작성) |
| 그 외 자유 서술 | progress | 일반 진행 메모 |

handoff 노트 필드: `완료한 것 / 검증 명령과 결과 / 검증 못한 것 / 문제와 해결 / 버린 접근 / 계획과 달라진 점 / 주의사항 / 변경 파일`

태스크 타이틀 프리픽스:
- `[retro] YYYYMMDD <계획명>` — 회고 다이제스트 게시물. 칸반 컬럼에서 **제외**하고 회고 뷰에만 표시
- `[lessons] 프로젝트 교훈` — 교훈 스냅샷 게시물 (최신 노트 = 현재 교훈). 칸반 컬럼에서 **제외**

## 뷰 1: 보드 카드 뱃지

```
┌─────────────────────────────┐
│ #12 대시보드 필터 버그 수정      │
│ ⚡High                       │
│                             │
│ 🔴 QA-FAIL ×2   ↩ 반려 1회    │
│ 👤 [human] 대기              │
├─────────────────────────────┤
│ dev-A            InProgress │
└─────────────────────────────┘
```

- `QA-FAIL ×n`: 해당 태스크의 QA-FAIL 노트 최대 회차. 0이면 미표시
- `↩ 반려 n회`: Rejected 전이 횟수. 0이면 미표시
- `👤 [human] 대기`: Review 상태 + 완료조건에 [human] 태그 존재 시
- `⛔ 블로커`: is_blocked=true 시 사유 툴팁

## 뷰 2: 태스크 상세 — 타임라인

```
┌──────────────────────────────────────────────────────┐
│ #12 대시보드 필터 버그 수정                    [Done]   │
│ 완료조건: ✅[auto] npm run build 통과                   │
│          ✅[human] 필터 초기화 동작 확인                │
├──────────────────────────────────────────────────────┤
│ ● 10:02 dev-A    착수 — 구현 계획: utils.ts의 ...      │
│ ● 10:41 dev-A 🔴 QA-FAIL 1회차: 빌드 시 타입 에러       │
│ ● 11:15 dev-A 📦 handoff                    [펼치기 ▼] │
│   ├ 완료한 것: 필터 상태 리셋 로직 수정                  │
│   ├ 문제와 해결: 타입 에러 → 원인: 제네릭 추론 실패      │
│   │   → 해결: 명시적 타입 파라미터 (추론 의존 회피)      │
│   ├ 버린 접근: useMemo 캐싱 — 상태 갱신 누락으로 폐기    │
│   └ 계획과 달라진 점: 없음                              │
│ ● 11:20      ⎇ commit a1b2c3 ":bug: [fix] #12 ..."    │
│ ● 11:34 Reviewer ✅ PASS — [auto] 재실행: build 통과    │
│ ● 14:02 user  👤 human-verified: 필터 초기화 확인       │
└──────────────────────────────────────────────────────┘
```

- 시간순 단일 타임라인. 작성자(개발/Reviewer/user)별 아이콘·색 구분
- handoff 노트는 필드별 접기/펼치기 — **서사 필드(문제와 해결/버린 접근)가 이 화면의 주인공**
- 커밋은 note가 아니라 커밋 메시지의 태스크 ID 매칭으로 표시 (가능한 경우, 없으면 생략)

## 뷰 3: 회고 목록 (`[retro]` 프리픽스 필터)

```
┌── 회고 ──────────────────────────────────────────────┐
│ ▸ 20260712 대시보드 개선   태스크 5 · PASS율 80% · 블로커 1 │
│ ▾ 20260708 서버 리팩토링   태스크 3 · PASS율 67% · 블로커 0 │
│     리뷰가 잡은 결함: 스코프 밖 변경 1건 (#8)              │
│     가장 자주 깨진 규칙: handoff '버린 접근' 누락 2회      │
│     튜닝 제안: MAX_QA_LOOP 3 유지, /quick 불필요          │
└──────────────────────────────────────────────────────┘
```

- `[retro]` 태스크의 description을 카드형 아코디언으로 렌더링. 요약 라인은 description 첫 줄

## 뷰 4: 교훈 (`[lessons]` 태스크의 최신 노트)

```
┌── 프로젝트 교훈 (lessons) ────────────── 최신: 20260712 ─┐
│ • SQLite WAL 모드 스키마 변경 시 -shm/-wal 잠금 확인      │
│ • 대시보드 빌드는 tsc 포함 npm run build로만 검증         │
│   (vite dev는 타입 에러를 안 잡음)              (20260708)│
└──────────────────────────────────────────────────────┘
```

- `[lessons] 프로젝트 교훈` 태스크의 **가장 최근 노트**를 마크다운 렌더링 (이전 노트 = 이력)
- 원본은 프로젝트의 `.claude/docs/lessons.md`이며 보드의 스냅샷은 /retro 시점 발행본 — 편집은 파일에서

## 비스코프

- 노트 편집/작성 UI (기록 주체는 에이전트, 보드는 읽기 뷰)
- retro/lessons 원본 md 파일 동기화 (발행은 /retro 커맨드 책임)
- 프리픽스 미준수 노트의 교정 (자유 서술은 일반 메모로 표시하면 됨)
